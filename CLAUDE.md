# Gym CRM — контекст проекта

## О проекте
CRM для тренажёрного зала в Уральске. Веб-приложение (PWA), которым пользуется
администратор/ресепшен зала для учёта клиентов, абонементов, оплат и посещений.

## Стек
- Next.js (App Router, TypeScript)
- Tailwind CSS
- Supabase (база данных + авторизация) — подключается на этапе 2
- Деплой: Vercel

## Структура проекта
```
app/            — страницы и layout (App Router)
app/register-sw.tsx — регистрация service worker (уже готов)
public/manifest.json, service-worker.js, offline.html — PWA-часть (уже готова)
```

## Утверждённый функционал (MVP)
1. **Клиенты** — карточка клиента (ФИО, телефон, дата рождения, фото), поиск и фильтр
2. **Абонементы** — типы (безлимит / N занятий / разовый), даты начала-окончания,
   статус (активен/истёк/заморожен), продление
3. **Оплаты** — сумма, дата, способ оплаты (нал/карта/Kaspi), история по клиенту
4. **Чек-ин** — отметка прихода клиента, история посещений
5. **Напоминания** — у кого абонемент истекает в ближайшие дни

## Этап 2 (после того как MVP обкатан)
- Расписание групповых занятий и запись на них
- Роли и права доступа (админ / владелец)
- Аналитика и отчёты (выручка, отток клиентов)
- Офлайн-запись данных (очередь чек-инов в IndexedDB с синхронизацией)

## Явно вне скоупа
- Нативное мобильное приложение (App Store / Google Play)

## Порядок разработки (двигаемся строго по шагам, не забегая вперёд)
1. CRUD клиентов на фейковых/захардкоженных данных (без БД) — чтобы сразу видеть UI
2. Подключение Supabase, перенос клиентов на реальную БД
3. Абонементы — привязка к клиенту, статусы
4. Оплаты — привязка к абонементу/клиенту
5. Чек-ин и история посещений
6. Напоминания об истечении абонемента
7. Полировка PWA (проверка установки на телефон, офлайн-чтение)

## Как работать над задачами
- Каждую фичу — маленькими шагами, с проверкой перед переходом к следующей
- Не предлагать функционал вне MVP без явного запроса
- Комментарии в коде — можно на английском, тексты в UI — на русском
